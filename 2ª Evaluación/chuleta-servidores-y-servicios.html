🔐 SSH — Acceso al servidor ▾
ConceptoDetalle
Puerto22
CriptografíaAsimétrica (2 claves)
Clave públicaEstá en el servidor → ~/.ssh/authorized_keys
Clave privadaEn tu PC → archivo .pem / .ppk
PassphraseContraseña extra que protege la clave privada
AlgoritmoED25519 (el que viste en el servidor)
Conectar con PuTTY + clave
Connection → SSH → Auth → Credentials → Private key file: clave.ppk → Open → login as: ubuntu
Conectar con CMD
ssh -i ruta\clave.pem ubuntu@IP

La clave privada NUNCA viaja por la red. Solo se verifica localmente.

🌐 HTTP / HTTPS — Puertos y cifrado ▾
ProtocoloPuertoQué hace
HTTP80Recibe la petición, redirige con 301 a HTTPS
HTTPS443Sirve la web con cifrado SSL
Flujo completo cuando entras a una URL
Escribes URL → DNS resuelve IP (wildcard) → Puerto 80 → 301 redirect → Puerto 443 SSL → NGINX regex → /var/www/$subdomain → index.html
Instalar certificado SSL gratis
sudo apt install certbot python3-certbot-nginx -y sudo certbot --nginx -d claseisidra.com -d www.claseisidra.com

⚙️ NGINX — Configuración y subdominios ▾
RutaFunción
/etc/nginx/sites-available/Cajón con TODAS las configs (activas o no)
/etc/nginx/sites-enabled/Solo los sitios ACTIVOS (enlaces simbólicos)
Activar / desactivar un sitio
sudo ln -s /etc/nginx/sites-available/web /etc/nginx/sites-enabled/ sudo rm /etc/nginx/sites-enabled/web
Flujo obligatorio tras editar config
Editar archivo → sudo nginx -t → sudo systemctl reload nginx

reload = aplica cambios sin cortar conexiones. restart = corta todo. Siempre -t antes de reload.

Regex de subdominios (alumnos-wildcard)
server_name ~^(?.+)\.claseisidra\.com$; root /var/www/$subdomain;

La variable $subdomain captura lo que sea antes del dominio. edicxon.claseisidra.com → /var/www/edicxon/

Truco para recordar: A = Address IPv4 | AAAA = cuatro A = IPv6 | CNAME = Canonical NAME = alias | MX = Mail eXchange

📦 SCP — Transferencia segura de archivos ▾

SCP usa el puerto 22 (igual que SSH). Cifra la transferencia.

Subir archivo (PC → Servidor)
scp archivo.txt edicxon@13.49.68.99:/var/www/edicxon/ scp -i clave.pem archivo.txt edicxon@IP:/var/www/edicxon/
Bajar archivo (Servidor → PC)
scp edicxon@13.49.68.99:/var/www/edicxon/archivo.txt C:\Users\User\Desktop\ scp -i clave.pem edicxon@IP:/ruta/archivo.txt C:\destino\
OpciónPara qué
-i clave.pemUsar clave privada en vez de contraseña
-P 22Puerto personalizado (P mayúscula)
-rCopiar carpeta entera (recursivo)

Primera vez: pregunta si confías en el servidor → escribir "yes" y pulsar Enter.

🧠 Preguntas tipo examen (con respuesta) ▾
1. ¿Qué es la criptografía asimétrica y cómo se usa en SSH?
Usa dos claves: pública (en el servidor, en ~/.ssh/authorized_keys) y privada (en tu PC, el .pem/.ppk). Al conectarte, el servidor te desafía con un problema que solo tu clave privada puede resolver. Si lo resuelves, entras sin contraseña. La clave privada nunca viaja por la red.
2. ¿Qué ocurre cuando entras a http://edicxon.claseisidra.com?
El navegador consulta el DNS → el wildcard *.claseisidra.com devuelve la IP del servidor → llega por el puerto 80 → NGINX redirige con un 301 al puerto 443 (HTTPS) → la regex captura "edicxon" en $subdomain → sirve /var/www/edicxon/index.html.
3. ¿Diferencia entre sites-available y sites-enabled en NGINX?
sites-available es el cajón con todas las configuraciones (activas o no). sites-enabled contiene enlaces simbólicos (accesos directos) a los sitios activos. Para activar: sudo ln -s. Para desactivar: sudo rm. Borrar el enlace no borra el archivo original.
4. ¿Qué hace esta línea: server_name ~^(?<subdomain>.+)\.claseisidra\.com$?
El ~ indica que es una regex. Captura cualquier subdominio y lo guarda en la variable $subdomain. Luego root /var/www/$subdomain; usa esa variable para saber a qué carpeta mandar al usuario. Un solo bloque sirve para todos los alumnos.
5. ¿Por qué se usa IP Elástica en AWS y qué tiene que ver con el DNS?
Sin IP Elástica, cada vez que reinicias el servidor la IP cambia. El DNS seguiría apuntando a la IP antigua y la web caería. La IP Elástica es fija aunque reinicies, así que los registros DNS (incluido el wildcard) siempre apuntan correctamente.
6. ¿Diferencia entre systemctl reload y restart nginx?
reload aplica los cambios de configuración sin cortar las conexiones activas. restart para NGINX completamente y lo vuelve a arrancar, cortando a todos los usuarios conectados. En producción siempre se usa reload. Y siempre precedido de sudo nginx -t para verificar que no hay errores.
7. ¿Para qué sirven los registros A, AAAA, CNAME, MX y wildcard?
A → nombre a IPv4 | AAAA → nombre a IPv6 | CNAME → alias (nombre a nombre, ej: www → dominio principal) | MX → indica el servidor de correo | Wildcard (*) → cualquier subdominio apunta automáticamente a la misma IP sin crear registros uno a uno.
8. ¿Cómo subirías el archivo web.html al servidor con tu clave .pem?
scp -i C:\Users\User\clave.pem web.html edicxon@IP:/var/www/edicxon/ — el orden es: scp → opción -i → clave → archivo origen → usuario@IP:destino
